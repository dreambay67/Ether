# Ether 2.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Ether 2.5 as a robust model-correction release around Nodes, Roles, and six payload Channels, with real backend effects, media interpretation infrastructure, graph migration, and updated Codex skills.

**Architecture:** Introduce canonical six-channel payload contracts, fixed role semantics, source/target channel edges, provider capability adapters, strict graph versioning, and a renderer channel-rail interaction model. Migrate old port/label graphs into 2.5 edges while preserving legacy data and disabling unsupported connections with explanations.

**Tech Stack:** Electron, React, TypeScript, Vite, @xyflow/react, SQLite, pnpm workspaces, Vitest, Playwright, Codex CLI provider workers, optional API/local provider infrastructure, DreamBay/Ether brand tokens.

---

## 0. Build Rules

- [ ] Treat 2.5 as a model correction, not a 2.1 polish pass.
- [ ] Do not implement scrollwheel role/channel selection.
- [ ] Use exactly six channels: Text, Image, Mask, Data, Video, Audio.
- [ ] Use exactly 15 roles: General, Negative, Subject, Product, Face, Clothing, Pose, Setting, Composition, Style, Lighting, Colour Palette, Typography, Motion, Timing.
- [ ] Assistant is not a node family.
- [ ] Prompt family has exactly five subnodes: Prompt, Brainstormer, Mutator, Expander, Reinforcer.
- [ ] Every allowed connection must have backend impact or be disabled with a user-facing reason.
- [ ] Audio/video interpretation must be provider/capability-gated. No placeholder media outputs.
- [ ] Preserve dirty worktree changes. Do not revert unrelated files.
- [ ] Add tests before or alongside implementation for each model change.

## 12. Final Failure Gates

The build fails if:

- [ ] any saved 2.5 graph lacks `graphVersion: "2.5"`;
- [ ] any canonical edge uses a non-six channel;
- [ ] any canonical edge uses a non-15 role;
- [ ] old port handles remain canonical edge semantics;
- [ ] old prompt subnodes appear in the node library;
- [ ] Assistant appears as a family;
- [ ] prompt assembly still depends on Prompt subtype names;
- [ ] allowed connections have no backend effect;
- [ ] invalid connections lack explanations;
- [ ] audio/video interpretation edges are enabled without provider capability;
- [ ] fake/API fallback happens without explicit user selection;
- [ ] migration drops legacy text, assets, roles, layout, or edges silently;
- [ ] migration is not idempotent;
- [ ] screenshot tests show old port clusters, overlapping labels, clipped inspector controls, or missing disabled states;
- [ ] Ether skills teach the old model.
