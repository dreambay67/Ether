# Ether 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Ether 2.0 into a professional local-first AI creative graph canvas with durable execution, first-class artifacts, clearer interactions, and explicit Codex-assisted workflow control.

**Architecture:** Move execution through a shared durable `RunCoordinator`, make SQLite canonical for revisions/jobs/artifacts/lineage, split large renderer files into focused modules, and keep desktop and MCP on the same engine services. The UI becomes canvas-first with project onboarding, typed nodes, typed ports, modular inspector panels, run previews, and an artifact browser.

**Tech Stack:** Electron, React, TypeScript, Vite, @xyflow/react, SQLite, pnpm workspaces, Vitest, Playwright, Codex CLI provider workers, MCP server.

---

## 0. Branch Decisions To Confirm Before Build

Use these defaults unless the user overrides them:

- SQLite is canonical for graph revisions, jobs, artifacts, and lineage. `graph.json` is a readable mirror.
- Durable foundation is Phase 1. UX shell and artifact browser follow immediately after.
- Fake provider remains available only as explicit Simulation Mode.
- Nano Banana Pro and Nano Banana 2 are capability slots until a clean CLI/MCP route is proven.
- 2.0 targets public-grade architecture with private-beta distribution.
- Codex can propose/apply graph edits after review, but generation runs require explicit user action.
- Video remains a reference artifact type only.
- Add optional API provider infrastructure for generation and assistant nodes, but keep CLI Codex as default and block hidden API fallback.
- Expand the bundled Codex plugin into advanced Ether workflow skills.
